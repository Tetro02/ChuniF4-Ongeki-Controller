# 上位机：检测与校准

在根目录执行 `python -m pip install -r host/requirements.txt`，然后 `python host/io4_hid_gui.py`。`--demo` 模式完全离线，不打开 HID。

## 十键与摇杆检测

扫描并选择设备，连接后逐个按下十个按键。卡片显示状态、按下次数及是否曾检测到。失去实时数据后卡片显示无数据，不能把过期状态当作当前按下。

摇杆显示原始 ADC、校准后的 0..65535 位置、范围及曲线。真正用于 IO4 的位置来自 Input Report byte 1..2；不是仅用于显示的模拟量副本。

## 三点校准与保存

1. 点击“开始校准”。
2. 移到物理最左，点击“记录左端”，固定约 200 ms 等待完成。
3. 移到中心位置，记录中心；再移到最右记录右端。
4. 需要时设置中心死区。单位为原始 ADC 计数，中心左右各 N 个；默认 0。
5. 点击“保存并应用校准”。只有设备最终回执确认持久化成功才算保存完成。

两个其他操作有独立含义：“仅应用到 RAM”立即使用校准，但重启后丢失这次 RAM 修改；“保存当前配置到 Flash”将已经生效的有效配置持久化。

记录过程中使用此前有效配置。三个采样点必须有足够行程且单调；电位器方向相反也可接受。采样期间晃动过大会被拒绝，应固定位置后重采该点。

## 超时和重启检查

保存等待最长 15 秒，不自动重试。超时或断连后先重新连接并查询状态；回执丢失不等于写入一定没完成。排队保存可取消，已经进入同步擦写的操作不能强行取消。

建议首次安装后完成一次实物验收：保存成功 → 正常断电 → 上电查询 `loaded_at_boot` 和 `persisted` → 检查左右和中心。这一步尚不能由软件故障注入替代。

只让一个上位机 / CLI 作为校准命令写入者。游戏期间避免执行 Flash 保存，擦写可能暂停 USB 服务。

## 游戏正常收到数据但角色不动

先看游戏测试菜单「入力テスト」的摇杆值是否变化；有变化说明数据已到达游戏。再到「レバー設定」，按画面提示缓慢移到左右端，退出保存。固件 Flash 校准不替代游戏自己的行程设置。

如果游戏左右反向，确认使用本仓库配套 DLL：固件物理左 / 中 / 右为 0 / 32768 / 65535，插件转为 -32768 / 0 / 32767。不要为了抵消旧插件方向而把上位机的“左端”和“右端”故意录反。
