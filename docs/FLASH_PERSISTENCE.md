# 摇杆校准 Flash 持久化固件

2026-10-17；基于原 `firmware/`，精确目标 STM32F411CEU6、512 KiB Flash。已完成源码集成、原生故障注入测试和 Keil 6.24 构建；未执行实物烧录或断电试验。图形上位机和 CLI 均已接入 Flash 保存命令。

## 已实现

上电在 `LeverCal_Init()` 自动扫描日志，选择最新的有效校准记录并启用。记录必须通过 magic、版本、长度、CRC、提交标记和锚点范围/顺序/最小跨度/死区检查；否则继续寻找上一份有效记录。没有有效记录时使用原始全量程映射，保持可检测。

新增两个明确的持久化命令。`09` 保存当前已启用配置；`0A` 保存待提交三点校准，成功后才替换有效配置。`05` 保持原来的 RAM 提交语义，以兼容原调用者。新 CLI 向导默认用 `0A`。

每个记录先写内容、逐字回读、再次核对整段内容，再写最后的有效标记，最后回读检查完整 CRC 和配置。只有最后校验成功，才回报 result=0 并设置 persisted。相同配置重复保存直接成功，不再编程或擦除。保存过程不会由 ADC/USB 中断调用。

## Flash 分区与布局保护

| 范围 | 用途 |
|---|---|
| `0x08000000..0x0803FFFF` | 程序，最大256 KiB |
| `0x08040000..0x0805FFFF` | sector6，校准日志 A，128 KiB |
| `0x08060000..0x0807FFFF` | sector7，校准日志 B，128 KiB |

扇区地址依据 [ST RM0383 §3.3](https://www.st.com/resource/en/reference_manual/dm00119316.pdf)。Keil 工程都使用新建的显式 `MDK-ARM/ChuniF4-flash.sct`，不依赖旧自动生成 scatter。IAR Flash ICF 同步缩小程序区，并登记新源码；IAR 本轮未编译。没有主动修改芯片选项字节、读写保护、启动模式或 BOR 配置。

运行时先检查设备 ID=0x431、工厂 Flash 容量=512 KiB，以及链接边界。容量不符或程序镜像侵入存储区时拒绝读取/写入，避免按 CE 的地址操作其他型号。HAL 后端只能擦除 sector6/7，只能在存储范围内执行对齐的32位写入。保存前解锁，结束后重新锁定 Flash。

后端在写入期间关闭并复位 Flash 数据缓存，确保读回的是新 Flash 内容，结束后恢复此前缓存状态。字编程使用 x32，要求板卡 VDD 保持 **2.7..3.6 V**，通常为3.3 V。电压条件及128 KiB扇区 x32 擦除时间（典型1秒、最大2秒）依据 [ST STM32F411CE 数据手册 Flash memory programming 表](https://www.st.com/resource/en/datasheet/stm32f411ce.pdf)。这些是文档参数，本轮未测量实物耗时或电压。

## 双扇区日志

一条记录32字节、每扇区4096槽位。先在当前有效记录所在扇区末尾追加。任何非全FF槽位都视为已占用，包括中断写入的半条记录，绝不重新写入。当前扇区满后，切换至另一扇区；需要时只擦除另一扇区，并检查全部字均为FF。整个切换过程中不擦除包含当前最新有效记录的扇区。新记录生效后也不立即清除旧扇区。

所有字段按小端固定编码，不直接写入含填充字节的 C struct。

| 偏移 | 内容 |
|---|---|
| 0..3 | magic=`0x4C43414C` |
| 4..7 | schema=`0x00010020`，版本1、长度32 |
| 8..11 | 32位递增序号，支持回绕比较 |
| 12..13 / 14..15 | left / center，原始 ADC |
| 16..17 / 18..19 | right / deadzone，原始 ADC |
| 20..23 | 保留，必须为0 |
| 24..27 | 对前24字节的 CRC32/IEEE，初值及最终异或为`FFFFFFFF`，反射多项式`EDB88320` |
| 28..31 | 最后写入的提交标记=`0xC011CA1B` |

invert 由三个锚点重新计算，valid 由记录校验产生，不把软件结构标志直接存入 Flash。CRC固定向量：序号1、左300、中2000、右3800、死区8时，CRC为`45E4E7F0`，已与 Python zlib.crc32 交叉验证。

## USB 命令与回执

保留原完整64字节格式：`10 C0 4C 43 01 seq op paramLE16`，余下55字节全0。09/0A 的 param 均须为0。

| op | 动作 |
|---|---|
| `05` | RAM提交，保持兼容；单独执行不会写 Flash |
| `09` | 保存当前有效配置；须先结束/取消采样会话 |
| `0A` | 校验三点、保存Flash、回读成功后启用；推荐用于“保存校准”按钮 |

收到09/0A后先排队，回传 result=11（保存中）。主循环等待包含该状态的 USB IN 传输完成，才调用同步 Flash 保存；无法发送或无法完成该传输超过3秒则取消排队并返回超时，不写Flash。排队期间可取消；真正进入同步写入后不能中途取消。

Flash 擦写期间 CPU 对单bank Flash的取指可能停顿，USB和SysTick服务可能暂停，本实现不承诺保存过程中1 kHz不中断。中断保持开启，没有用关中断包围依赖 HAL tick 的擦写。CLI 对09/0A等待最长15秒，且不会自动重试。仅应在校准/维护时保存，不在游戏实时输入期间频繁写入。

输入Report的29字节LC状态布局与原版相同。flags（完整Input byte41）新增：

- bit4 `persisted`：当前有效配置与已知保存成功的Flash配置一致。
- bit5 `loaded_at_boot`：本次上电曾从Flash成功加载；后续RAM修改不会清除此历史位。
- bit6 `saving`：保存命令排队/处理中。
- bit7 `flash_supported`：芯片容量与布局检查通过。

新增result：11保存中、12Flash操作失败、13没有有效校准、14芯片/Flash布局不支持、15回读校验失败。原10表示操作超时，现在也用于保存通知超时。

主机须匹配seq+op，等待最终结果；result=1或11均不是成功完成。09/0A必须收到result=0且persisted=true才显示“保存成功”。超时或USB中断后应重新查询当前状态；已写完标记但主机未收到最终回执时，不能仅凭超时认定数据没有保存。

## 命令行操作

```powershell
python host/lever_calibrate.py wizard --deadzone 0
```

按提示执行物理左、中、右采集，每点保持约200 ms。向导最后自动使用0A保存并应用。也支持：

```powershell
python host/lever_calibrate.py save
python host/lever_calibrate.py commit_save
python host/lever_calibrate.py status
```

`save`保存已启用值，`commit_save`保存当前完整待提交会话。`status`可查看persisted和loaded_at_boot。图形版的“仅应用到 RAM”不写 Flash；“保存并应用校准”使用 0A，“保存当前配置到 Flash”使用 09。

## 构建与验证范围

打开 `firmware/MDK-ARM/ChuniF4.uvprojx`，target `ChuniF4`。公开版本已移除原工程的 AfterMake 自动烧录动作；编译不会烧写板卡。

仓库根目录运行 `python scripts/check.py` 进行软件测试；Keil 构建使用 `scripts/build-firmware.ps1`。故障注入使用可替换的NOR Flash后端，不会访问真实MCU或模拟成实物测试。

已验证：

- 原有三点映射、反向、deadzone、平均采样和异常命令测试通过。
- 初次保存和已有旧记录两种情况下，分别在8个写入边界制造中断，共16组；重启扫描排除半写记录，有旧记录时恢复旧值，无旧记录时fallback。
- 逐一损坏记录8个字、版本/CRC/标记，能退回旧记录；CRC正确但锚点非法仍拒绝。
- 缓存无关的存储核心测试、重复配置免写、解锁失败、回读损坏、提交标记实际完成但底层返回错误、32位序号回绕、扇区轮换和部分擦除失败。
- 通过0A的事务式启用、通过09保存RAM值、模拟上电自动恢复、取消排队、通知超时、不支持芯片时不读取越界存储区。
- 从当前`IO4_Task`提取原函数体，模拟IN尚未完成、取消、两种通知超时、USB重连，确认未完成保存通知前不写Flash。
- Keil Arm Compiler 6.24全量编译/链接：0错误、0警告。最终二进制大小和镜像边界见构建日志、map及验证结果文件。

尚未验证：烧入真实F411CEU6后断电重启、实测擦除期间USB表现、供电跌落试验、看门狗选项字节状态、游戏端兼容性。上述软件故障模型不能代替实物断电验收。若芯片选项字节强制开启独立看门狗，首次上板需核实其超时大于可能的擦除耗时；本轮不改写看门狗或选项字节。

升级时应只擦写程序覆盖的扇区0..5，以保留校准。整片擦除或擦除sector6/7会清空记录；firmware HEX/BIN不含预填充的校准日志。CubeMX重新生成后需复核scatter/ICF、两个存储源文件的登记和手工HID改动。
